# Agent 执行手册

[English](03-agent-handoff.md)

本文件用于新聊天或实现分支的任务交接。先交付 M0a/M0b，并按探针结果建立 M0c，再推进 M1–M5。卡片状态为待开始、进行中、阻塞或已验收；写明阻塞不等于完成。M6 独立排期。

## 可直接交给主 Agent

> 在 `~/dev/MosBot_Desktop` 从零重做 MosBot Desktop。读本目录四份方案，以 `docs/scratch/录屏2026-11-03 19.25.26.mov` 为界面参考，从 `~/dev/MosBot` 取品牌资产。先推进 M0a 可运行窗口和 M0b 指定真实服务探针；界面经用户操作验收后冻结。真实联调固定 `192.168.2.171:9119` 与 OAuth，写入限本次专用测试对象。发现缺失必交能力时建立 M0c 修复任务，不能用隐藏或降级关闭卡片。完成新 Bot 授权到首条回复、文件交付、后台提醒、工作台、电脑非抢占接管及 M5 安装升级和 7 天日用验收后，才交付完整首版。每卡附复现命令、证据、负责人和未解决事项。

开始前核对目录、现有 Git 状态和权限，保留其他改动及原录屏。`docs/plans` 随 Git 保存，录屏、缓存、凭据和真实联调原始数据继续排除。主 Agent 独占根构建配置和共享类型写入，依据总计划固定依赖锁文件；按 AGENTS.md 分阶段验证提交并更新双语 changelog，不擅自推送。本次计划修订不代表 M0 已实施。

## M0a · 能操作的界面切片

- **起点**为录屏第 00:42、00:46、01:04、01:24、02:03、02:14 的状态。先用大约 1000 × 760 的真实 Electron 窗口验收双栏比例，再验证 720 × 500 的覆盖式详情栏。
- **交付**包括正常的启动脚本、真实 MosBot 徽标和 BotFace、布局、脱敏 fixture 和浏览器/Electron 自动测试入口。Fixture 最少有两个分区、六个置顶位、超长中文名、空对话、长回复、离线、权限确认和电脑休眠。选 Bot、折叠分区、搜索后跳转、打开关闭详情、实时试形色均能操作。
- **完成门槛**为裁切截图、键盘/IME 验证、短操作录屏和用户实际试用结论。记录待调整项并复验；未通过时继续修正界面，协议、存储等独立工作可进行。后续 M1/M4 接真实响应，M5 再验安装包。

## M0b · 协议与部署探针

唯一集成验收目标为 `192.168.2.171:9119`，使用系统浏览器 OAuth。先只读确认版本、scheme、前缀、身份、权限和插件；地址策略按 02 的精确测试 origin 规则执行。创建带本轮标识的专用 profile、board/任务及测试文件，记录对象 id，仅清理本轮对象。需要登录时由用户在浏览器输入，令牌安全保存且不入报告。不启动替代 Dashboard 或 mock server，也不为造故障修改全局插件、active profile 或重启共享服务。局部断网、客户端进程重启和双客户端竞争可用于真实异常验收；部署变更先完成可审查补丁、影响和回退说明，再在当次授权范围内执行。

| 验证顺序 | 探针必须留下的结果 |
| --- | --- |
| 1. REST 探活与认证 | `/api/health`、`/api/status`、provider 列表、浏览器回调、换码、`/api/auth/me`、刷新和注销；必须记录指定服务完整 OAuth 链路，包含取消、刷新失效和重新登录。记录版本、身份是否匹配、前缀、代理行为。只保存脱敏后的字段形状 |
| 2. WS 与已有 Bot | 一次性 ticket 握手、过期和重复使用拒绝、`gateway.ready`、`profiles.list`、精确 Bot Chat 查询、resume、首个真实 delta、停止、持久历史回读。记录哪些事件带 turn id 或消息 id |
| 3. 新 Bot 与双客户端 | 先在不继承凭据的新 Bot 上走授权、选模型、真实首回复和重启续聊；再用两个进程同时 lookup/create/title。至少一次制造标题冲突或 pending，确认各自的 stored id、胜出记录、prompt 实际归属和可见历史。重复以同账号双端 resume、断线及审批，核实另一端能否继续观察、停止和回复请求 |
| 4. 工作台 | 独立 profile 的列表/详情/分页/搜索/模型配置回读；Kanban 可用时的 board 快照和游标、测试卡片新建/状态更新。切 board 时旧事件不得更新新 board；缺失插件记录阻塞，不擅自切换全局状态 |
| 5. 文件与后台 | 上传图片/文件并让模型实际读取；生成产物后分页索引、预览、保存、外部打开。另验未打开 Bot 的审批、跨端处理、通知拒绝、关主窗口与 Dock 重开、退出重启和重新登录 |
| 6. 电脑 | 能力、状态、唤醒、缩略图、RFB 握手、观看、租约取得与归还。验证两 viewer 争用及断线回到只读，记录目标部署能否保证 lease 判定与 acquire 间的并发安全 |

**交付物**为可重跑探针、脱敏 fixture 和 `docs/evidence/capabilities.md`。每行含「能力 / 本地与部署版本 / 请求结果 / 必交或扩展 / 已验证、待验证或缺失 / 负责人 / 依赖卡 / 关闭证据」。能力可分批验收，已有 Bot 链路通过即可做 M1；所有必交缺口进入 M0c，不能从表中删除以通过验收。

## M0c · 后端依赖闭环

主 Agent 对交付结果负责，开工时为每项填入实际负责人和依赖卡。协议负责人确定差异和最小兼容契约，实现负责人交付适配或后端补丁，测试负责人在指定部署复验。角色不可用时由主 Agent 承接并记录，不以无人负责搁置。

| 依赖 | 当前依据及解决产物 | 关闭条件 |
| --- | --- | --- |
| 电脑非抢占控制 | 本地 `c419cf7c86` 的 acquire 为后来者覆盖；补齐服务端原子条件认领、冲突回执和兼容探测。部署情况由 M0b 实测 | 指定服务两 viewer 并发仅一方成功；失败方不能输入/释放赢家租约，断线和迟到回执正确；关闭 M4 阻塞 |
| 新 Bot 可用性 | 验证 profile 定向授权/模型配置及 canonical 标题认领；缺失则补配置入口、状态回读或认领能力 | 干净新 Bot 完成真实首回复，双端竞争不重复发送，重启续聊；关闭 M1/M2 阻塞 |
| 资料交付 | 验证有来源的产物元数据和授权下载；缺失则补后端资源引用或可验证适配 | 真实产物可定位来源、保存并打开，跨 profile 被拒绝；关闭 M4 阻塞 |
| 后台请求与工作台 | 验证全 Bot 待处理请求发现及 Kanban 等必要能力；缺失则补协议/插件部署兼容方案 | 未打开 Bot 的请求可处理、跨端回执同步，工作台写入回读；关闭 M1/M3 阻塞 |

每项保留缺失证据、补丁位置、最低兼容版本、部署影响/回退和复验命令。补丁完成但尚未部署或复验仍为阻塞。不可修改的后端依赖由主 Agent 提交具体范围决策，只有用户明确变更首版范围后才能移出；等待期间继续独立任务。

## 实施顺序和阻塞处理

| 卡片 | 工作顺序与具体交付门槛 |
| --- | --- |
| M1 · 聊天 | 真实登录、名单、历史和回复 → 恢复/审批/停止 → 全 Bot 提醒及窗口生命周期 → 草稿持久化。已有 Bot、切 Bot、关窗重开及断线对账验收通过；与 M2 联验新 Bot 首发 |
| M2 · 创建与整理 | 新建 profile → CAS 外观 → 原 profile 授权/模型配置 → 状态回读 → canonical 认领 → 真实首回复 → 重启续聊；再验分区/置顶/搜索、部分成功和并发冲突。未配置时保留步骤和草稿，不判完成 |
| M3 · Hermes 工作台 | 三个子页直接使用真实 REST，Kanban 使用真实 WS 游标重连。用独立测试对象演示配置或状态写入和回读，验证主界面恢复原聊天。插件禁用显示专用空态，其他页面仍可用 |
| M4 · 资料与电脑 | 文件上传/产物索引 → 预览/保存/打开 → 电脑状态/唤醒/观看 → 非抢占接管/归还。先交付只读窗口可作为进度，但 M4 关闭必须有完整真实链路和 M0c 关闭证据 |
| M5 · 发布与日用 | 性能和双语/外观/键盘回归 → 签名公证 → 干净安装完整流程 → 从前一测试版覆盖升级、迁移失败恢复 → 连续 7 天真实日用 → 用户最终验收。每项分别记录结果 |
| M6 · 群聊及语音 | 依据各自 M0b 能力证明单独排期、实现及验收。群聊和录音按参考录屏保持原来的入口层级 |

**并行方式**为视觉和协议先行，主 Agent 统一接口。M0a 通过后展开完整 UI，M1 与 M2 按冻结契约协作，M3 复用 M2 配置逻辑，M4 等对应能力通过；M5 仅在 M1–M4 全部验收后关闭。真实登录、服务写入、GUI 录屏和签名串行。发生阻塞必须记录负责人、下一动作和复验条件，同时继续独立工作。

## M5 交付清单

- 提供版本化签名安装包、校验值、支持的 macOS/架构/后端矩阵、发布说明和已知限制；真实部署未验证的版本不宣称支持。
- 根目录 `README.md`（英文）和 `README-zh.md`（中文）说明安装、OAuth 连接、模型配置、通知、文件保存、手动覆盖升级、恢复与反馈入口。双语 changelog 同步；计划、测试与证据文档同样中英双语（英文主文件在原路径 + `-zh` 中文版）。
- `docs/evidence/acceptance.md` 按 README 每个验收项索引命令、版本、结果和脱敏证据，区分 fixture、真实服务、签名安装包及用户验收。缺失服务能力的降级测试只能证明异常处理。
- 连续 7 天实际使用包含真实聊天、审批、产物、工作台、电脑、休眠恢复和重启；记录每天结果。无数据丢失、重复发送、越权及未解决阻断问题；修复后重测受影响流程，日用可靠性修复重新开始连续观察。
- 必交项全部通过且用户完成最终操作验收才交付；不得把仍缺凭据、服务能力、签名或用户验收的产物标为完整首版。

## 提交证据的最低格式

为仓库建立稳定的脚本名，建议 `pnpm dev`、`pnpm typecheck`、`pnpm test`、`pnpm test:e2e`、`pnpm test:contract`、`pnpm bench:stream`、`pnpm make`。这些脚本由对应阶段实际提供。另提供 `pnpm test:integration` 真实联调入口，由环境配置注入测试地址和身份。测试通过日志须标明实际跑的是 fixture、真实服务还是安装包。

每次交接附上卡片编号、变更范围、复现命令、环境与版本、结果和证据路径，以及下一张卡或阻塞条件。至少用以下断言检查主链路。

- 已有 Bot Chat 发送后，刷新读回一条用户消息；跨端打开同一持久会话；离线中回复继续、重连可恢复且停止可达。
- 同一个新 Bot 的两个客户端争用标题，任何候选都要经过持久确认才允许提交；待确认或冲突客户端保留草稿。
- Profile A 的迟到消息、授权结果及附件不会写到 Profile B；注销和切账号后旧事件失效。
- Kanban 改状态有服务器回读，切 board 后回放限定于原游标范围；电脑 viewer 的控制状态与服务端租约一致。
- 未打开 Bot 的审批可发现，另一端处理后回执同步；后台通知不重复，注销后旧通知不能打开其他账号数据。
- 真实附件及产物在重连/重启后可继续访问；新版本覆盖安装保留草稿、分区和偏好，迁移失败可恢复。
